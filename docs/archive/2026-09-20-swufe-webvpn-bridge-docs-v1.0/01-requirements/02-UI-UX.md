# 交互与 UI/UX 设计 — Phase 1

## 1. 设计原则

1. **官方登录为主**：CAS/MFA 在 WebView 内完成，App 不仿登录表单。
2. **状态可见**：连接/断开/错误一眼可辨。
3. **危险操作可逆**：CA 安装有风险提示；必须能一键卸载；开关关闭即恢复网络默认行为。
4. **少即是多**：第一期不做复杂策略组/节点订阅 UI。

## 2. 信息架构

```text
主窗口
├─ 顶部状态条（连接状态 / 简短错误）
├─ 主操作
│  ├─ [登录 WebVPN] / [重新登录]
│  └─ [开启桥接] 开关
├─ Allowlist
│  ├─ 默认 jwxt.swufe.edu.cn
│  ├─ 添加 / 删除
│  └─ [ ] 启用 *.swufe.edu.cn
├─ 证书
│  ├─ [安装本机 CA]
│  └─ [卸载本机 CA]
├─ 高级（可折叠）
│  ├─ 系统代理状态说明
│  ├─ 进程捕获：选择浏览器等进程（可选列表）
│  └─ [ ] 调试日志
└─ 日志面板（调试开启时）：域名 | 改写结果 | 时间
```

可选：托盘图标显示连接状态（非第一期必做）。

## 3. 关键用户流程

### 3.1 首次使用

1. 启动 → 引导条：「需要安装本机证书才能处理 HTTPS」
2. 用户确认风险 → 安装 CA → 系统可能要求输入密码/允许
3. 点击「登录 WebVPN」→ WebView 打开门户/CAS
4. 用户完成认证 → App 检测会话成功 → 状态「已登录」
5. 确认 allowlist → 打开「开启桥接」
6. 若系统已有代理 → 模态框阻止并说明关闭 Clash 等
7. 提示用浏览器访问教务

### 3.2 日常使用

1. 启动 → 若 Cookie 仍有效可显示「已登录」（若无法静默验证则要求重登）
2. 开桥 → 用浏览器
3. 用完关桥或退出（退出须清代理）

### 3.3 会话过期

1. 桥检测到 401/登录页跳转/Cookie 失效（实现定义探测信号）
2. 自动：停桥、清系统代理、停进程捕获
3. 模态：「会话已过期，请重新登录」→ [去登录]

### 3.4 卸载 CA / 卸载 App

- 设置内「卸载本机 CA」
- 退出/卸载说明：关闭桥后卸载证书

## 4. 界面状态

| 状态 | 状态条 | 开关 | 说明 |
|---|---|---|---|
| 未登录 | 灰色「未登录」 | 禁用 | 需先登录 |
| 已登录未开桥 | 蓝色「已登录」 | 可开 | |
| 桥接中 | 绿色「桥接中」 | 可关 | |
| 错误 | 红色 + 原因 | 视情况 | 如「系统代理被占用」 |
| 过期处理中 | 橙色 | 强制关 | |

## 5. 文案要点（中文）

- CA 安装警告：本证书用于在本机解密并改写 HTTPS，仅限个人设备；可随时卸载。
- 代理冲突：检测到系统代理已启用。请先关闭 Clash / mihomo / 其它 VPN 的系统代理后再试。
- 过期：WebVPN 会话已失效。桥接已停止并已清除系统代理。

## 6. 无障碍与平台

- 按钮具备清晰标签；错误不仅靠颜色
- macOS / Windows 遵循各平台窗口与权限对话框习惯
- 不强制暗色主题（可跟随系统，非必须）
